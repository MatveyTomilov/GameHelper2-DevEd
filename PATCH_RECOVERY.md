# Восстановление GameHelper2 DevEd после обновления PoE 2

Запускайте команды восстановления из локального дерева, подготовленного `dev/build-local.ps1`. Оно содержит закреплённые исходники хоста, структуры игры и историю для репетиции. Подробные отчёты предыдущих этапов находятся в локальном интеграционном дереве. Upstream Sync отмечает возможные исправления в сторонних репозиториях, а их пригодность проверяется отдельно для конкретного клиента. [Сопоставление upstream](UPSTREAMS.md)

1. Зафиксируйте рабочий Release и профиль. Храните ZIP, SHA‑256 и `developer-build.json` целиком. `recover.ps1 -NewWorktree -ClientExe '<путь к EXE>' -RuntimeDirectory '<стабильный runtime>'` создаст изолированный `recovery/*`, снимок EXE и копию runtime. Сравните версию, Steam Build ID, SHA‑256 и результаты с последним рабочим `recovery.json` через `-BaselineReport`. [Скрипт](recover.ps1)
2. Сверьте `phases.signatures` и `diagnostics/signatures.json`. Сканер требует единственного совпадения и адреса внутри PE. Ghidra проверяет декодирование инструкции и назначение её операнда. Укажите `-GhidraHome` и `-JdkHome` либо `-InstallTools` для закреплённых загрузок с проверкой SHA‑256. При необходимости запустите `-Offline -Framework -FrameworkAnalysisProfile Recipe -AnalysisTimeoutSeconds 720 -FrameworkPostTimeoutSeconds 600`. Для нового патча оценивайте семантику каждого кандидата и фиксируйте пропущенные сайты и тайм-ауты. [Сканер](dev/SignatureCheck/Program.cs) · [Версии инструментов](dev/tools.json)
3. Для проверки структур используйте отдельный runtime и `GH_OFFSET_DUMP`. Сверьте Entity, Actor, Life, Render, UI и Terrain с данными загруженной области. Для контрольной поломки используйте `dev/test-structure-recovery.ps1`. Уникальный лидер поискового прохода подтверждается второй проверкой после пересборки. [Проверка структур](dev/test-structure-recovery.ps1)
4. Зафиксируйте правку на изолированной ветке и запустите `./recover.ps1 -CandidateSource '<чистый worktree>' -TrialCandidate`. Сценарий собирает отдельный Release, проверяет манифест, переносит копию профиля и запускает диагностическую копию. Для чтения текущих игровых данных используйте `dev/start-plugin-smoke.ps1` и `dev/test-plugins.ps1`. Для Atlas2 откройте `WORLD → ENDGAME`, для LootValue дождитесь цен и откройте инвентарь или сундук, для Radar закройте панели и откройте карту области. Для проверки торгового плагина используйте автоматические тесты или загрузку без запуска сессии. [Запуск smoke](dev/start-plugin-smoke.ps1) · [Сценарии](dev/test-plugins.ps1)
5. При выводе в работу сохраните базовый отчёт через `./recover.ps1 -RuntimeDirectory '<проверенный runtime>' -SaveBaseline`. Для отката остановите кандидат и запустите `candidate.rollbackRuntime` либо распакованный стабильный ZIP с его профилем. Проверьте хеши, PID и подключение MCP. Используйте отдельный каталог для каждого набора DLL. [Сборка пакета](package.ps1) · [Проверка манифеста](dev/runtime.ps1)

Историческая репетиция `./dev/rehearse-recovery.ps1` привязана к известному EXE Steam 0.5.5h и проверяет обнаружение двух старых масок, пересборку, а в режиме с загруженной областью — структуры и пробный откат. `-Offline` подходит для статического прогона. Точные результаты миграционной проверки приведены в [REPOSITORY_SETUP_REPORT.md](REPOSITORY_SETUP_REPORT.md).
