## Восстановление после патча

На Steam 0.5.5h сканер нашёл **6/6 уникальных статических сигнатур** с прежними RVA. Точечная проверка инструкций Ghidra прошла. Скрипт создал изолированный worktree, копию рабочей версии и отчёт сравнения клиента. При живой инъекции шести неверных полей и повторной сборке подтверждены **4/6** на одном экземпляре области. Это Entity ID, Actor ActiveSkillsPtr, UI Self и Terrain TileDetailsPtr. Life Health и Render CurrentWorldPosition остались неоднозначными. [Инструкция](PATCH_RECOVERY.md)

Автопоиск Recovery Framework в режиме `Standard` с бюджетом анализа 300 секунд повторил **1/6**. Анализ исчерпал лимит, кандидат GameCullSize подтвердился, пять рецептов не подтвердились. Предыдущий локальный аудит с `Recipe` и бюджетом 720 секунд показал 4/6. Офлайн-репетиция обнаружила обе намеренно устаревшие маски, восстановила их, собрала и упаковала кандидат. В этом режиме кандидат остался `PARTIAL` до пробного запуска. Отчёты интеграции находятся в `artifacts/recovery/20261124-095642-2cc19ede`, `artifacts/rehearsals/20261124-100316-cde49b93` и `artifacts/structure-audit/58ea35fb97`.

## Upstream Sync

Один Linux job отслеживает Gordin/GameHelper2, gahehe/GameHelper2Fork, MordWraith/Gamehelper, TahiKari/ExileCenter и ExFy0/GameHelper2-Offset-Recovery-Framework без включённого ПК. Ветка `upstream/state` хранит наблюдаемую ревизию отдельно от интегрированной. Свежие времена опросов сохраняются как артефакт. Локальный инструмент выборочного переноса проверен на `3f1b541` с выводом коммитов и изменённых файлов. [Конфигурация](dev/upstream/sources.json) · [Процедура переноса](UPSTREAMS.md)

- **10 тестов Upstream Sync** прошли на ПК и Linux runner GitHub. Проверены классификация, теги, лицензии, неполное сравнение, сохранение состояния при HTTP 503 и дедупликация. [Тесты](dev/upstream/test_monitor.py) · [Запуск fixture](https://github.com/MatveyTomilov/GameHelper2-DevEd/actions/runs/45345855506)
- Два ручных запуска обработали пять реальных источников. Повторный сохранил SHA ветки состояния `88051ff1bb2a9637e9dc8a2d53ee24babde2d7dd`. Оба сохранили артефакт времени. Измеренное время job — 16 и 11 секунд. [Первый запуск](https://github.com/MatveyTomilov/GameHelper2-DevEd/actions/runs/45344034855) · [Повторный запуск](https://github.com/MatveyTomilov/GameHelper2-DevEd/actions/runs/45344175982)
- Первый тест API выявил задержку списка GitHub и создал два явно тестовых Issue, оба закрыты. После исправления тест создал и закрыл одну запись. Повторный запуск нашёл тот же номер. Ложных уведомлений об изменениях реальных upstream не было. [Исправление](https://github.com/MatveyTomilov/GameHelper2-DevEd/commit/95c116c) · [Создание](https://github.com/MatveyTomilov/GameHelper2-DevEd/actions/runs/45344458528) · [Повтор без дубликата](https://github.com/MatveyTomilov/GameHelper2-DevEd/actions/runs/45344762682) · [Тестовая запись](https://github.com/MatveyTomilov/GameHelper2-DevEd/issues/3)
- Cron настроен на минуты `07` и `37` каждого часа. При одной округлённой минуте на запуск — **1 440–1 488 минут** за 30–31 день, эквивалент **$2.88–$2.98** включённого вычислительного лимита. При двух минутах за запуск в 31-дневном месяце — **2 976 минут (~$5.95)**. Это часть общего GitHub Free лимита **$12**. В настройках владельца уже есть бюджет Actions **$0.00** со статусом **Usage blocked**. Ручные проверки успешно использовали включённый лимит. [Тарифы и инструкция установки $0](UPSTREAMS.md)
- GitHub подтвердил активность workflow на `main`. На момент приёмки первый отдельный запуск с событием `schedule` ещё не появился. Ручной запуск подтвердил работу того же job и режима `monitor`. [История запусков](https://github.com/MatveyTomilov/GameHelper2-DevEd/actions/workflows/upstream-monitor.yml) · [Расписание GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## Обновление и откат

Для обновления обработайте Issue в ветке `upstream/*` или `fix/*`, зафиксируйте исходный SHA и автора, запустите локальный Release и регрессию, затем откройте PR в `develop`. После проверки продвиньте `main` и выпустите следующий тег DevEd. Для патчей PoE начните с изолированного сценария восстановления. [Перенос](UPSTREAMS.md) · [Восстановление](PATCH_RECOVERY.md)

Для отката остановите тестовый процесс, проверьте SHA‑256 стабильного ZIP и распакуйте его в отдельный каталог, либо используйте `candidate.rollbackRuntime`. Подключите копию проверенного профиля, запустите без старта продажи и проверьте манифест, MCP и загрузку плагинов.
